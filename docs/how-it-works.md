# Investment Helper backend

The frontend is plain HTML, CSS and JavaScript. A Cloudflare Worker serves it through OpenAI Sites and fetches public stock histories and currency rates. Cloudflare D1 stores the private portfolio ledger and watchlist. GitHub stores the source code; a Site deployment keeps running independently of your computer.

Portfolio insights use the same JavaScript calculations as Portfolio and Reports. The authenticated evidence endpoint reads the saved portfolio and public market data; it does not change records or call an AI provider. The browser writes plain-language explanations from those figures. A manually prepared ChatGPT summary can include optional position notes and is copied only on an explicit click. Opening ChatGPT sends no portfolio data in the URL. The paid analyst endpoint is retired; no `OPENAI_API_KEY` is required.

## Personal ChatGPT plugin (MCP)

`get_latest_changes` reads completed coding-task records from the separate D1 `development_changes` table, newest first (default one, maximum twenty). It uses exactly the same owner authorization as the investment tools. The additive migration does not modify portfolio or watchlist tables. Records survive Worker restarts and redeployments, with one immutable record per workspace/commit for safe upload retries.

The required end-of-task workflow is documented in `AGENTS.md`. After committing/pushing and receiving a terminal Sites deployment result, `npm run task:complete` accepts bounded completion metadata and the existing app password through hidden stdin. It derives the Git hash and modified-file list automatically, executes the selected targeted tests, and uploads counts/results plus explicit limitations and deployment receipt status/time. No test logs, environment objects or native tool responses are stored. A task with no deployment explicitly records `not_deployed`; no testing explicitly records `not_run`. Deployment status is the reported receipt, not an independent live status poll. The command must be run at task completion: Git alone cannot infer task boundaries, human summaries, limitations or Sites publication results. Missing/failed uploads are reported, not silently presented as completed records.

The private ingestion endpoint (`POST /api/development-changes`) retains the existing password cookie, same-origin and expected-account checks. It is not an MCP write tool. It only accepts a fixed metadata schema, rejects credential paths and unexpected fields, and redacts common credential/environment assignments; the completion helper additionally removes its own password from submitted text. Use concise reviewed descriptions and never supply secrets as prose. Existing changelog rows are revalidated before being returned.

The same Worker exposes a stateless JSON-RPC `POST /mcp` endpoint. The `mcp` capability in `.openai/hosting.json` lets Sites provision a private personal plugin when published and refresh its tool catalogue on later publications. Use the plugin Sites creates under **Plugins → Personal → Created by you → Investment Helper**; no separate server, AI API key or local MCP configuration is needed. Sites provides the connection URL and handles its authentication. The website still opens with its existing password.

`server/mcp.mjs` handles discovery (`server/discover`), legacy client initialization, tool listing and five retrieval tools:

| Tool | Returns |
| --- | --- |
| `get_portfolio_holdings` | All recorded positions, quantities, native/actual EUR cost bases and cash; no raw transactions or notes. These are recorded positions, not current valuations. |
| `get_watchlists` | The saved cloud watchlist, revision and successful save time. Missing saved data is not replaced with browser defaults. |
| `get_stock_prices` | Validated prices for 1–20 exact symbols, currencies, quote/close distinction, sources and observation times. Uses the website's existing price loader and backups. |
| `get_financial_metrics` | Annual company financial metrics, reporting periods, source links, successful retrieval times, and stale/missing/retained warnings. ETF company metrics can be unavailable. |
| `get_data_loading_status` | Server-side record and provider checks, per-symbol errors and timestamps. Defaults to at most 20 held/watched tickers and reports unchecked coverage; browser scan progress is unavailable. |

For privacy on this public-entrance Site, every tool call requires Sites' authenticated user ID and verified email matching the server-only `INVESTMENT_MCP_OWNER_EMAIL` runtime secret. Configure that value from the verified Site owner before deployment. Discovery exposes only the fixed tool definitions, never personal data. An anonymous caller, another signed-in visitor, a browser password cookie, an arbitrary bearer value or a supplied workspace ID cannot authorize a tool call. Normal pages and APIs retain the password gate; MCP authorization never grants access to them.

The MCP data layer only reads the existing `password_workspace` mapping and its saved records. It cannot create a workspace, change a revision, import a book, save a watchlist or execute a trade. No database migration is required. Tool annotations also mark every operation as read-only, but enforcement comes from the fixed dispatch table, strict input validation and storage reads. Inputs cannot supply SQL, arbitrary URLs or account IDs. Public provider requests carry only public ticker information, never portfolio quantities, costs, cash or notes.

`latestSuccessfulUpdateAt` means the successful save time for portfolio/watchlist, the actual market observation time for prices, and the successful per-company retrieval time for financial metrics. It is never overwritten by a failed refresh or by the current `checkedAt` response time. The price source does not retain a separate successful download time, so the original quote/daily-close observation time is explicitly labelled instead. Financial `lastUpdateAttemptAt` and accounting `periodEnd` are separate fields. Multi-symbol responses include individual timestamps and the oldest/newest successful timestamps; the newest is not a claim that every item is current. Unavailable fields are null with error codes, not estimated or converted to zero. Stale financial figures can be returned with their original dates and explicit warnings. A completely unavailable result sets MCP `isError: true`; partial responses retain usable rows and identify failures.

## Access and storage

The Site entrance is publicly reachable and the Worker protects the app with a personal password. ChatGPT sign-in is not required. The password hash and a random session-signing key are runtime secrets, never source or browser assets. Successful login creates a signed, HttpOnly session cookie that lasts 30 days. HTTPS cookies are Secure and scoped to this host; POST sign-out clears the current browser cookie. Changing either secret invalidates existing sessions.

The server checks the cookie before serving app pages, JavaScript, data assets or private APIs. Platform identity headers cannot bypass password mode. A bounded same-origin login form verifies a salted PBKDF2 hash; D1 counts login attempts atomically across Worker instances. Missing secrets or unavailable authentication storage fail closed.

Both portfolio and watchlist use one personal workspace key. The first authenticated password request retains the sole existing storage identity from these tables, including every revision. If both tables are empty, it creates a stable workspace identity. Multiple existing identities require an explicit server-side selection and never silently merge. An optional `INVESTMENT_WORKSPACE_ID` runtime value can select the exact existing identity. Authentication metadata is separate from portfolio records.

Every storage read and write is authorized server-side. D1 statements bind the authenticated workspace and supplied values rather than interpolating them. Personal API responses are `private, no-store`. Mutations require JSON, the same origin, the expected workspace identity and an expected record revision. Requests are streamed within a 1 MiB limit. Anyone who knows the app password accesses the same personal portfolio.

A save uses one conditional SQL statement: create only if the record is absent, or update only if its revision matches. When another phone or tab already saved, the stale writer receives a conflict and must reload. A timed-out save can have reached the server, so the app requires a read before retrying rather than assuming nothing changed. Changed or expired sign-in blocks private controls and hides the previous account's data.

Portfolio books retain the existing settings, opening holdings, transactions and original source text. Cloud validation uses the same ledger model as browser storage. The cloud book is limited to 1 MiB and the watchlist to 90 unique symbols. Research-pick journals, scan results and view preferences remain browser-local in this first backend version.

## Moving the existing portfolio

1. Open the GitHub Pages app in the browser containing your transactions.
2. Under **Portfolio → Backup and restore**, choose **Export backup**.
3. Open the Sites app and enter the app password.
4. Choose that backup in **Backup and restore**, review the preview, then restore it.
5. Open the same Sites address on your phone and enter the same password. It loads the saved cloud ledger.

An existing cloud book is never replaced by an automatic browser upload. An explicit upload button is available only when the current Site origin has an old IndexedDB book and the cloud portfolio is empty. Since GitHub Pages and Sites have different origins, the backup route is normally needed. The original local book is retained. Transfer a custom watchlist separately by copying its symbols into **Watchlist → Edit as text**.

Confirmed cloud books also keep an owner-scoped IndexedDB recovery copy. Cloud requests never silently switch to local writes during an outage. Exported JSON backups remain available for recovery. Reload cloud data refreshes both records; the app checks for changes when returning to the page without resetting an open editor.

## Market data

### Loading and diagnostic batches

The Data sources page includes independent Portfolio, Watchlist, Prices and Financial metrics checks. Record reads finish independently of market providers. Market checks page through the full held/watched list in batches of 10 or 20 with 1–3 concurrent ticker requests; one ticker failure does not reject the batch. Existing results remain visible during manual refresh. Per-ticker details are collapsed by default and show source, currency, quote/close type, successful observation time and structured errors. A changed record revision during pagination stops that check and asks for a refresh rather than combining shifted ticker pages. Diagnostics only read saved records.

`get_data_loading_status` preserves its existing arguments/results and adds `offset` (default 0), `batchSize` (1–20, default 20), `concurrency` (1–3, default 2), and `component` (`all`, `records`, `prices`, `financialMetrics`). Continue with `pagination.nextOffset` until null; `totalTickers`, `remainingTickerCount` and `listRevision` describe coverage. `uninspectedTickerCount` still means tickers outside this response, not confirmed failures or cumulative session coverage. Explicit `tickers` continue to work. Top-level market freshness excludes record saves; `portfolio.savedAt` and `watchlist.savedAt` are separate. A read-only password-protected `/api/loading-status` serves the website using the same data layer.

MCP errors consistently include `code`, `message`, `ticker`, `provider`, `retryable` and `lastSuccessfulQuoteAt` (nullable when unknown). Protocol errors use the same object in JSON-RPC `error.data`. Stale quote errors preserve the successful observation timestamp. Missing company data and known ETF unsupported metrics have different codes. An empty/no-longer-valid cache remains unavailable rather than zero. Per-source failures do not remove other successful component results.

The fundamentals snapshot request retries transient network/5xx failures once with bounded backoff, shares its request/cache, respects a 429 cooldown, and retains the last successfully loaded public snapshot when later requests fail. Yahoo price requests retain the existing shared exponential cooldown and Retry-After behavior. No CAPTCHA or provider block is bypassed. The published snapshot is a fallback transport for Yahoo-derived data, not an independent exchange feed.

Browser bulk portfolio histories can return recent validated cached data immediately and refresh the public-price cache in the background. A refresh event recomputes displayed portfolio values without writing holdings, transactions or cost bases. Callers explicitly requesting a fresh single-ticker history retain awaited loading; they can opt into `backgroundRefresh`. Cached observations are never given a new market timestamp. Server caches remain isolate-local; published backups remain the cross-deployment fallback, and recent-history validation still applies.

VICR is included in scheduled price and company-financial publishing. Missing company records report a coverage/provider error; only known funds receive the ETF-specific error. The existing SEC companyfacts publisher selects annual filings and matching annual durations, preserves period/source provenance, derives free cash flow only from matching cash-flow/capital-expenditure periods, and leaves missing debt/EPS concepts unavailable.

Yahoo retries use capped exponential cooldowns for network errors, server errors and rate limits, respecting a longer Retry-After. Concurrent ticker requests remain deduplicated. After all available sources fail, the Worker can retain its last successful in-memory history with an explicit stale flag. MCP propagates that flag and the original quote timestamp. This cache is isolate-local, bounded to 80 histories, and is lost on cold starts/deployments. MCP still rejects histories older than seven days. Published snapshots provide the existing cross-deployment backup for covered symbols. An independent quote fallback remains conditional on permitted provider access; no new unverified no-key source is enabled.

ETF exposure fetches Vanguard's full public portfolio pages for FTSE All-World, verifies their row count, identity and common observation date, then groups the stock rows by issuer. Share classes and verified US ADR/local-share aliases combine without guessing foreign ticker identities. Current EUR fund values are multiplied by dated stock weights; residual fund value is kept separate. Company, country and sector totals reconcile to known holdings value. Reports page company results in groups of 25 and export all matching rows.

Sites keeps a six-hour isolate-local public fund cache, refreshes through authenticated GET `/api/fund-holdings`, and falls back to the embedded complete snapshot. GitHub Pages refreshes the generated browser module daily/on publication. Neither path sends holdings, amounts or visitor credentials to Vanguard. Partial pages, duplicates, mismatched dates and malformed data reject the whole refresh. Retained data keeps its original dates; weights older than 120 days are not used. Insights consumes the same source and coverage.

Holding EUR cost basis comes from the actual EUR cash paid in each buy, including fees. Partial sales remove the weighted-average EUR cost of the shares sold. EUR unrealized gain is current EUR value minus the remaining recorded EUR cost, so it includes exchange-rate changes on the invested capital. Native USD figures remain available alongside it. Foreign opening positions or purchases without EUR settlement records show an unavailable EUR return rather than an invented historical cost. The projection is derived from existing transactions; no ledger migration or financial-record rewrite is needed.

The hosted frontend sends only a ticker to `GET /api/market/history`. The Worker requests a fixed Yahoo Finance chart URL and validates its identity, currency, dated daily prices and splits. Public results are cached briefly and concurrent requests for the same ticker share one request. Yahoo failures can use the latest real GitHub-published snapshot for covered symbols, followed by the deployment's bundled snapshot if it is still recent. Missing history stays unavailable. Market data never invents prices or changes the observation date during a retry.

The GitHub publisher optionally requests a dated Leeway quote when Yahoo fails, enabled only by the Actions secret `LEEWAY_API_TOKEN`. This fallback changes the latest quote, not the Yahoo daily history or split records. Both the Worker and frontend preserve **Leeway delayed quote** as its source. A private workflow counter limits attempts to 40 per UTC day; it never stores the token. The independent provider remains inactive until a free token is configured and ticker access is checked.

Outbound requests use Worker-compatible options with manual redirect handling; non-success responses, including redirects, are rejected. Browser-only credentials and the unsupported `redirect: "error"` mode are omitted. Tests exercise this behavior in the compiled Worker as well as the source module.

`GET /api/exchange-rate` loads the dated ECB USD-to-EUR reference rate through Frankfurter. `GET /api/portfolio-fx` supplies five years of historical reference rates for the existing supported currencies. Both can recover from a provider failure using the validated GitHub-published snapshot and then a recent bundled snapshot. Current rates and the latest history observations must be no more than seven days old; fallback retains the actual publication and observation dates. Provider requests have bounded deadlines, and the browser allows enough time for recovery. These references value holdings; manually recorded EUR settlements remain authoritative. News research, financial snapshots and ticker suggestions keep their existing sources. The backend does not place trades.

## Schema and deployment

`.openai/hosting.json` links the source to its Site and declares the logical D1 binding `DB`. Sites provisions storage and applies the generated schema-only migrations before publishing. `db/schema.ts`, `drizzle.config.ts` and the append-only `drizzle/` files define those migrations. Production requests never create tables.

Run `npm install` once for development tools, `npm test` for checks, and `npm run db:generate` after schema changes. `npm run dev` starts a loopback preview with a synthetic local identity and a separate SQLite database in ignored `.sites-runtime/`. To check the password gate, run `npm run build`, set the local `PREVIEW_PASSWORD` environment variable to a disposable test password, then run the preview. Password preview serves the actual Worker bundle; rebuild it after edits. Preview secrets and data cannot authenticate a hosted visitor. Local previews and tests apply the same SQL as D1.

`npm run build` bundles the Worker and an explicit allowlist of public browser assets into `dist/server/index.js`. Large assets use gzip to keep the Worker small. Only the Sites build enables cloud storage in the embedded HTML; the tracked frontend and GitHub Pages remain browser-local. Server files, secrets, local SQLite databases and Git metadata are not served as browser assets. Build output and runtime state are ignored by Git.

Configure `INVESTMENT_AUTH_MODE=password`, secret `INVESTMENT_PASSWORD_HASH`, and secret `INVESTMENT_SESSION_SECRET` through Sites runtime settings. `generatePasswordSecrets()` in `server/auth.mjs` creates the salted hash and random key. Keep credentials in memory and out of Git and command arguments. Publish and verify the password gate before enabling the public Site entrance. The Sites source workflow pushes the exact Git state and packages the matching build. GitHub Pages' existing scheduled publisher still refreshes public market snapshots; it publishes only the frontend assets prepared by `scripts/build-github.mjs`.
